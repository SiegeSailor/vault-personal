# General Classification of Index Tables

Almost all Database uses B+ Tree as the default index data structure.

- Primary Index
- Clustering Index
- Secondary Index

Index file. `<field_name>` is the key:

```
| ------------ | --------------- |
| <field_name> | Block Pointer   |
| ------------ | --------------- |
| ...          | <block_address> |
```

## Primary Index

Built on an ordering key field (in an ordered file), such as `ssn` in `employee`.

Tables stored as Disk Blocks, there is a few tuples in one block. For example, `ssn` 1, 5, and 8 tuples are in block 1, 9, 10, 11 are in block 2, and so on. Index file only stores the key attribute of the **first** tuple of a block as the key, and then we can find the targeted tuple since we know where the block is pointed to.

The first tuple in a block is so called a _Block Anchor_.

## Clustering Index

Sparse Index. (non-dense index)

Built on an ordering non-key field, such as `dno` in `employee`. A block pointer pointes to the first block contains the corresponding key. If a block's last tuple have the key, then the DBMS would keep searching the next block.

## Secondary Index

Dense Index.

Built on a key or non-key; file is not ordered by the column. Same with Primary Index, but the tuples in blocks are not sorted, and it uses tuple address instead of block address.

## Tree Structure

We usually use binary-search tree for **in-memory** storage. Database is not an in-memory storage, so we expend the concept.

### B+ Tree

- A node is always half full

```
| pointer | key | pointer | key | pointer | key |
```

- A tree is always balanced
- All keys are at the leafs
- Some keys are copied in the internal nodes
