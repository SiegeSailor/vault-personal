# Mapping ER to relation table

If there are 2 optional relationships (even when they are in the same entity) or 2 many-to-many relationships, create a third cross-reference table. Otherwise, put foreign key primarily on table who has mandatory participant or non-many relationship because we don't want null value or duplicated rows.

Relationship attributes follow where the primary key is (or third table).

Foreign key goes with Weak entity first.
