```
    T
  /   \
 T1   T2
```

If decomposition from T to T1 and T2 not done correctly, when we use join to restore the result, it may result in additional tuples or lost tuples, which is not a lossless JOIN.

## Functional Dependencies

- Is a constraint
- Determined by a schema
- Must hold in all valid states

In a given table, if I know the value of X, then I can always find Y: $X \implies Y$ where X and Y are set of attributes:

| COLUMN | ... | ssn | ... | fname |
| ------ | --- | --- | --- | ----- |
| t1     | ... | x1  | ... | y1    |
| t2     | ... | x2  | ... | y2    |

If t1[ssn] = t2[ssn] Then t1[fname] = t2[fname]

If a column has values that are all unique, then it may hold FD to all other columns even if other columns have duplicated data (ex: SSN -> salary | SSN -> address...)

## Normalize

RDB Schema R
|_> Normalize R to 1NF (automatically satisfied with RDBMS)
|_> Normalize R to 2NF
|_> Normalize R to 3NF
|_> Normalize R to BCNF

If a schema R is in BCNF, then it is already in 3NF and 2NF

### 1NF

```
R
| ssn | pnumber | hours | ename | pname |
 ---------------
  |        |        ^       ^       ^
  |        |        |       |       |
  |________|________|_______|_______| <- fd1
           |                        ^
           |                        |
           |________________________| <- fd2
  |                         ^
  |                         |
  |_________________________|         <- fd3
```

- fd1: full FD
- fd2: partial FD
- fd3: partial FD

### 2NF

Defined with regard to partial functional dependency.

A relation R is in 2NF, if no non-prime attribute is partially dependent on the primary key of R. Otherwise, R violates 2NF.

> `hours`, `ename`, `pname` are non-prime attributes, which is not a part of any key

The relation R is not in 2NF due to fd2 and fd3 violate 2NF

To correct, we copy the left hand side and remove the right hand side from fd\*:

```
R is decomposed to:

R
| ssn | pnumber | hours

R1
| pnumber | pname |

R2
| ssn | ename |
```

### 3NF

| ssn (PK) | name | dnumber | mgrssn | dname

fd1: ssn -> dnumber
fd2: dnumber -> mgrssn, dname

fd2 violates 3NF because it is transitively dependent on ssn

A relation R is in 3NF if R is in 2NF and there is no non-prime attribute that is transitively dependent on the primary key of R.

## General Definition

- 2NF: If a non-prime attribute is partially dependent on any key (primary key and candidate key)
- 3NF: A relation R is in 3NF if for every f.d X -> A, (1) x is a super key or (2) A is prime (of any key)
- BCNF: A relation R is in BCNF if for every f.d X -> A, x is a super key
- 4NF: Multi-valued dependency. Rare
- 5NF: Join dependency. Rare and difficult to identify
