## CREATE VIEW

```sql
USE company;

CREATE VIEW department_information(name, number_of_employees, total_salary)
AS
SELECT department.dname, COUNT(*), SUM(employee.salary)
FROM department, employee
WHERE department.dnumber = employee.dno
GROUP BY department.dname;
-- or
CREATE VIEW department_information
AS
SELECT department.dname AS name, COUNT(*) AS number_of_employees, SUM(employee.salary) AS total_salary
FROM department, employee
WHERE department.dnumber = employee.dno
GROUP BY department.dname;
```

## Virtual Table vs Materialized View

| Category          | Speed | Space  |
| ----------------- | ----- | ------ |
| Virtual Table     | Slow  | N/A    |
| Materialized View | Fast  | Needed |

Materialized View is usually implemented in database warehouse for OLTP(Online Transaction Processing) due to the amount of time for computing for aggregate functions. It requires updates, with DBA (immediate, lazy, periodic) or triggers.

## Update

Update to a virtual tables depends on DBA. Usually update without aggregate values is allowed (because aggregate values are computed from basic tables) since DBA knows how to map the updated value to their original tables (or only views created from single table allowed).

## Relational Algebra

(One will appear in the final exam)

- Objects: Relations (Tables)
- Operations: JOIN, SELECT, PROJECT ,All set operations (UNION, INTERSECTION, DIFFERENCE)

For $\pi$ PROJECT, it removes all duplicates, which is different from SQL

For natural join, R1 \* R2, it will automatically introduce all columns with the identical name. To specify only the columns we want, use $\bowtie$

For difference, R1 - R2, order matters, and columns names don't have to be the same (but data type has to be the same).
